# 2026-08-04 工作日志

## PMS→AI表格同步 401 故障诊断

- **现象**: exe 程序 (pms_sync_windows) 跑增量同步，4 个 PMS 接口全部返回 HTTP 200 但业务码 code=401，"authentication failed"，8 个错误，同步失败。
- **实测验证**: 用用户提供的 token 直接 curl 调用 4 个 PMS 接口，全部成功：
  - 物料 `/pms/system/kc/material/list` POST → total=22
  - 仓库 `/pms/system/warehouse/list` GET → total=7
  - 订单 `/pms/kc/order/list` POST → total=56
  - 库存 `/pms/system/inventory/find-records` GET → total=687
- **根因**: token 本身有效，`Authorization: Bearer xxx` 传法正确。exe 11:45 跑失败是因为当时用的是已过期的旧 token。PMS token 为 JWT(HS512)，payload 仅含 `login_user_key`，无 exp，有效期由服务端 Redis session 控制，session 过期则 token 失效。用户在故障后重新登录拿到新 token（即本次验证用的），新 token 有效。
- **19 vs 22 条差异**: 用户浏览器拿 19 条，程序拿 22 条。差异为请求参数不同——程序发 `{"baseId":152,"current":1,"size":100}` 不带过滤，会拿到含 status=0 停用物料(FQ998/FQ999 等)的全部 22 条；浏览器带了筛选只拿 19 条。与 401 无关。
- **代码可改进点**:
  1. 缺 token 预检：建议同步开始前先发轻量请求验证 token，失败直接退出，避免跑完全表才报 8 错。
  2. 错误计数虚高：每个 401 记 2 条 ERROR("PMS 返回错误" + "→Token 已失效")，导致 error_count=8 实际仅 4 个失败请求。建议第二条降级为 warning 或不重复计数。
- **下一步**: 用有效 token 重跑 exe 即可。

**关键经验**：dws CLI 的 destructive 命令(delete)在脚本/Agent 调用时必须加 `--yes`，否则会卡在交互确认。

## dws 找到但 WinError 193（第4次修复）

用户 dws 装在 `D:\npm-global\`（自定义 npm 全局目录）。`where dws` 返回 `D:\npm-global\dws`（**无扩展名的 Unix shell 脚本**），subprocess 直接执行报 `WinError 193: %1 不是有效的 Win32 应用程序`。npm 装包时同时生成 `dws`(shell脚本) + `dws.cmd`(Windows批处理)，应优先用 .cmd。

修复 `_find_dws()` 第3步（where dws）：结果按扩展名优先级排序 `.cmd > .exe > .bat`；若只找到无扩展名的，查同目录下的 `dws.cmd`。重新打包成功（run 30891656593），新 exe MD5=aef34462503c64a2317da7e9c676b060。

**关键经验**：Windows 上 `where dws` 可能返回无扩展名的 shell 脚本（npm 生成），subprocess 无法执行（WinError 193）。必须优先选 `.cmd`/`.exe`/`.bat` 扩展名，或查同目录的 `.cmd`。

## dws.cmd 执行 stdout=None（第5次修复）

dws 正确找到 `D:\npm-global\dws.cmd`，但 `subprocess.run([dws_bin]+args)` 直接执行 .cmd 文件，Windows CreateProcess 无法直接跑 .cmd → `result.stdout` 为 None → `json.loads(None)` 崩溃 TypeError。

修复 `dws_cmd()`：Windows 上 .cmd/.bat 文件用 `["cmd", "/c", dws_bin] + args` 执行；同时加 stdout None/空防护 + stderr None 防护。重新打包成功（run 30892248096），MD5=ba92f36c19691d74069981a8931a0e29。

**关键经验**：Windows 上 Python subprocess 执行 .cmd/.bat 必须用 `cmd /c` 包一层，否则 CreateProcess 无法捕获 stdout（返回 None）。这是 PyInstaller 打包的 exe 在 Windows 调用 npm 全局命令的常见坑。
